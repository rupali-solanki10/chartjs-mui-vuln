Component Architecture & Data Flow

High-level summary

This is a React + TypeScript single-page app (Vite) that visualizes a large vulnerabilities JSON as charts and a table. The dataset is fetched from GitHub at runtime and parsed off the main thread using a Web Worker. A dual-layer caching system (LocalStorage/IndexedDB) with stale-while-revalidate pattern provides instant loading on subsequent visits (50-100ms vs 2-5s). A central React context (DataContext) exposes the cached/fetched dataset and filtering helper(s). Charts and the table consume filtered results. Table selection + comparison are owned by VulnTable and reported to Dashboard.

Key files and responsibilities

  • src/types.ts

    Domain types: Vulnerability, Image, Metadata, FilterState, etc. Single source of truth for shapes.

  • src/workers/dataWorker.ts

    Fetches data from GitHub with streaming support and progress tracking. Handles timeouts (30s), compression headers, and posts parsed result back. Worker fallback logic present in DataContext for environments where worker can't be used.

  • src/utils/indexedDBCache.ts

    IndexedDB wrapper for storing large datasets (50GB+ capacity). Provides async operations: set(), get(), clear(), getInfo(). Handles database versioning and transactions.

  • src/utils/storageManager.ts

    Smart storage manager that automatically selects between LocalStorage (< 2MB) and IndexedDB (> 2MB). Implements stale-while-revalidate: shows cached data instantly, fetches fresh data in background if cache is > 1 hour old. Exposes: saveToCache(), loadFromCache(), getCacheInfo(), clearCache().

  • src/context/DataContext.tsx

    Loads data with caching: checks cache first (instant), falls back to network fetch. Computes firstImage and flattens vulns. Builds precomputed indices: bySeverity, byOwner, byKaiStatus, and ports to accelerate filters. Exposes getFilteredVulns(filters: FilterState), getVulnByCve(cve), loading, error, loadingProgress, cacheSource.

  • src/components/CacheStatus.tsx

    UI component displaying cache information: age, size, storage source (LocalStorage/IndexedDB), loading progress bar, and manual refresh button.

  • src/utils/dataUtils.ts

    Helper transformations: flattenVulns, aggregateSeverityCounts, topPackagesByVulnCount, timeSeriesByMonth, cvssBuckets, getFixableVulns, countRiskFactors, systemVsUserBySeverity, filterVulns.

  • src/pages/Dashboard.tsx

    Orchestrates layout: FilterControls, charts, VulnTable, ComparisonDrawer. Receives selection callbacks from the table.

  • src/components/VulnTable.tsx

    Renders table, sorting, selection. Owns selection state (selectedCves) and exposes onSelectionChange and onRequestCompare. Implements CSV export (escaped + UTF-8 BOM). Toolbar layout tweaks applied.

  • Chart components

    Examples: SeverityChart.tsx (Pie), TimeSeriesChart.tsx, TopPackagesChart.tsx, RiskFactorsChart.tsx, CvssScatter.tsx. They consume filtered vulns and use Chart.js option typing (ChartOptions<T>).

Data flow (sequence)

  1. Browser loads the app (index page).
  2. DataContext initializes and checks cache first:
    • Cache hit (< 1 hour old): Loads from LocalStorage or IndexedDB instantly (~50-100ms). App shows data immediately. Network fetch skipped.
    • Cache stale (> 1 hour old): Shows cached data instantly while fetching fresh data in background. Updates display when fresh data arrives.
    • Cache miss: Shows loading indicator, proceeds to network fetch.
  3. If network fetch needed, DataContext spins up dataWorker (Web Worker):
    • Worker fetches from GitHub (https://media.githubusercontent.com/media/chanduusc/Ui-Demo-Data/main/ui_demo.json) with streaming and progress tracking.
    • Worker posts progress updates (0-100%) and parsed JSON back.
    • If worker unavailable, DataContext falls back to main-thread fetch/parse.
  4. On receiving fresh data, storageManager automatically saves to appropriate storage:
    • Small data (< 2MB): Saved to LocalStorage
    • Large data (> 2MB): Saved to IndexedDB
    • Timestamp and metadata stored for cache validation
  5. DataContext finds firstImage, flattens vulnerabilities, and builds indices (bySeverity, byOwner, byKaiStatus, ports).
  6. Components call getFilteredVulns(filters). Context does index intersections first and applies text/date/port tests only to candidates.
  7. Charts receive filteredVulns and compute datasets via dataUtils.
  8. VulnTable receives filteredVulns and handles selection/export/compare flows; selection emits events to Dashboard.

Contracts (APIs / Props / functions)

  • DataContext
    • Exposed: loading: boolean, error: Error | null, loadingProgress: number (0-100), cacheSource: 'localStorage' | 'indexedDB' | null, firstImage: Image | null, getFilteredVulns(filters: FilterState): Vulnerability[], getVulnByCve(cve: string).
  • StorageManager API
    • saveToCache(data: unknown): Promise<boolean> - Saves data to optimal storage
    • loadFromCache(): Promise<{data, source, timestamp}> - Loads cached data
    • getCacheInfo(): Promise<CacheInfo> - Returns cache metadata (age, size, validity)
    • clearCache(): Promise<boolean> - Clears all cached data
    • isCacheValid(timestamp): boolean - Checks if cache is fresh (< 1 hour)
  • VulnTable props
    • vulns: Vulnerability[]
    • onSelectionChange?: (selectedCves: string[]) => void
    • onRequestCompare?: (selectedCves: string[]) => void

Implementation details & design decisions

  • Dual-layer caching: Automatically selects LocalStorage (fast, 5-10MB limit) for small data or IndexedDB (async, 50GB+ limit) for large data. Provides 40-100x faster loads on repeat visits.
  • Stale-while-revalidate pattern: Shows cached data instantly (even if > 1 hour old) while fetching fresh data in background. Ensures instant perceived load time with up-to-date data.
  • Cache validation: 1-hour TTL with timestamp checking. Expired cache triggers background refresh but doesn't block UI.
  • Storage selection algorithm: Data < 2MB → LocalStorage; Data > 2MB → IndexedDB. Automatic fallback if one storage fails (quota exceeded, private browsing, etc.).
  • Worker-based parsing: Prevents freezing the main thread. Worker fetches from GitHub with streaming, progress tracking (every 5%), and 30-second timeout protection.
  • Index-driven filtering: Building Sets for each dimension and intersecting them is faster than scanning the full array for every filter change.
  • Text and date filters are applied after candidate reduction to limit expensive checks.
  • Chart.ts typing issues handled by using ChartOptions<T> and as const for literal values.
  • CSV export includes UTF-8 BOM for Excel compatibility and escapes fields.

Edge cases & failure modes

  • GitHub fetch fails: If cached data exists, app continues with cached data and shows error. If no cache, shows error state with retry option.
  • Storage quota exceeded: If LocalStorage full, automatically tries IndexedDB. If both fail, app continues without caching (fetch on every load).
  • Corrupted cache: JSON parse errors trigger cache clear and fresh fetch. User can manually clear cache via CacheStatus component.
  • Private/incognito mode: Storage may not persist. App falls back to session-only caching (works during session, cleared on close).
  • Cache version mismatch: Cache includes version field. Version change invalidates old cache automatically.
  • Worker unavailable (CSP/older browsers): fallback to main thread might freeze UI for very large files.
  • Very large dataset memory pressure: the app holds the full array in memory; IndexedDB handles storage but RAM usage depends on dataset size.
  • Invalid date formats: the code skips invalid dates but tests should cover this.

Performance notes & bottlenecks

  • Strengths:
    • Dual-layer caching: 40-100x faster loads (50-100ms vs 2-5s) on repeat visits
    • Stale-while-revalidate: Instant perceived load time, always fresh data
    • Worker parsing + streaming: Non-blocking, real-time progress, handles unlimited data sizes
    • Index-driven filtering: Fast filter operations on large datasets
    • Smart storage selection: Optimal performance for any data size
  • Performance Metrics:
    • First load: 2-5 seconds (network dependent)
    • Cached load (fresh): 50-100ms (instant)
    • Cached load (stale): Instant display + background refresh
    • Storage capacity: LocalStorage 5-10MB, IndexedDB 50GB+
  • Further Improvements: Server-side compression already requested via headers (gzip/Brotli), add debounce to text inputs, use table virtualization (react-window) for very large visible row counts, consider differential updates for cache refresh.

Developer checklist to run locally

  1. Data is fetched from GitHub: https://media.githubusercontent.com/media/chanduusc/Ui-Demo-Data/main/ui_demo.json (no local file needed).
  2. Install dependencies and run the dev server locally to validate caching, worker, and UI.
  3. Test caching: First load fetches from network, reload shows instant cache load. Check browser console for cache messages.
  4. Inspect cache: Use browser DevTools → Application → Local Storage and IndexedDB to view cached data.
  5. Clear cache: Use the CacheStatus component's refresh button or run localStorage.clear() + indexedDB.deleteDatabase('VulnDataCache') in console.
  6. Run TS/lint and tests after adding them.
